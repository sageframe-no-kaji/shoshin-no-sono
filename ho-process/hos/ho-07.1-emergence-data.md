# ho-07.1 — Emergence data: dating the corpus, the missing works, the edelmore split

## Problem

ho-07.2 renders the world-then-writing emergence: peaks rise in the order they
were conceived, renamed works pulse when they were named, then the writing towns
arrive in their own dated order. The catalog can't support that today.

- **No trustworthy origin date.** `created` and `publication_date` are estimates —
  ho-01 flagged it for software, ho-07 confirmed `created == publication_date` for
  all six writing pieces. There is no field that carries when a work was *conceived*.
- **Three core works are missing.** `sageframe` (~2025-04, "the start of ALL of
  this," live at atmarcus.net/work/sageframe), `shodo` (the LLM corpus search
  engine), and `sutra` (the git-controlled writing surface) — shodo and sutra are
  core R&D tooling, not minor entries — are absent from the MVP sample.
- **`edelmore` is one entry that's actually two** — a diary and a reader.
- **The naming-after-conception case has nowhere to live.** forteller / palana were
  conceived as Kṣetra-Ops (~2025-08) and named later (2026-03-21); the data carries
  only one moment.

ho-07.2 is blocked on real data. This ho writes the practitioner's emergence
archaeology — captured in [emergence-chronology.md](../pre-work/emergence-chronology.md)
— into the catalog behind a small schema addition. No rendering; the Indexer
absorbs the new fields and exposes them for ho-07.2.

This pulls a slice of catalog authoring forward out of Phase 3 (the chain defers
full hydration to ho-12.5). That's deliberate — the animation demands real data —
and it stays bounded: the works and dates the emergence story needs, not the whole
body of work. Hand-authored here rather than through the Founder (ho-12), which
doesn't exist yet; the Founder's bulk pass in ho-12.5 inherits these fields.

## Solution

A focused, editorial catalog pass — the ho-01 register (practitioner + Claude
editorial loop, per-entry, validated), not an agent task and not a script.

Two schema fields carry the emergence story:

- **`conceived`** — ISO date, the origin. The moment the idea entered. This is the
  rise moment in ho-07.2.
- **`named`** — ISO date, optional. Set only when a work was named meaningfully
  after it was conceived. The pulse moment in ho-07.2. Most works are
  conceived-and-named together and omit it.

Dates carry the *order* and *simultaneity*; ho-07.2 plays even beats, so a 3-year
gap or a fuzzy month never distorts pacing. Provisional dates are allowed and
flagged — order is what matters, and the order is firm.

## Changes

- **`schema.json`** — document `conceived` (origin date) and `named` (optional
  later-naming date) in the descriptive contract, next to `created` /
  `publication_date`, with the conceived-vs-named convention written out.
- **`scripts/validate-works.mjs`** — enforce ISO-8601 (`YYYY-MM-DD`) on both;
  `named` optional; `conceived` required for non-`archived` works (archived
  pre-history may predate reliable records — decide at execution).
- **`works.json`** —
  - **Add** `sageframe` (conceived ~2025-04; genesis; high importance; group and
    relationships authored minimally; deployment → atmarcus.net/work/sageframe).
  - **Add** `shodo` (conceived 2026-03-04; LLM corpus search engine; core, high
    importance; group `infrastructure` proposed).
  - **Add** `sutra` (conceived 2026-03-04; git-controlled writing surface; core,
    high importance; group `infrastructure` proposed).
  - **Split** `edelmore` → `edelmore-diary` (conceived 2026-05-14) and
    `edelmore-reader` (in progress). Migrate any relationships pointing at
    `edelmore`; decide id inheritance (see confirmations — `edelmore` is MVP-sample
    on `labs`, not yet shipped, so the id is not yet permanent).
  - **forteller / palana** — `conceived` ~2025-08 (Kṣetra-Ops), `named` 2026-03-21.
  - **Author `conceived`** across every existing work from the table, including the
    six writing towns (their order drives the writing phase of the animation).
- **`src/indexer.js`** — `getWork()` already returns the whole work, so `conceived`
  / `named` ride along for free; add JSDoc typedef entries for the two fields and a
  small accessor only if ho-07.2's read wants one. No new query stage required.

No rendering changes. No `cartographer.js` / page changes. ho-07.2 owns all of that.

## Execution-time confirmations

Decisions small enough to settle in the authoring loop, named so they're not
silent:

- **Provisional dates** — `sageframe` (~2025-04), Kṣetra-Ops (~2025-08),
  `m4bookmaker` (late Feb / Mar 2026). Pin if quick, else accept provisional and
  flag in the entry. Order is firm regardless.
- **shodo / sutra group** — `infrastructure` proposed (alongside forteller /
  palana); confirm or place elsewhere.
- **Importances** — sageframe, shodo, sutra are core → high prominence. Set by feel
  against the existing importance spread.
- **edelmore id handling** — does one of the two inherit `edelmore`, or do both get
  fresh ids and `edelmore` retires? Whichever, migrate inbound relationships.
- **`conceived` required vs optional** — required for non-archived; confirm the
  archived exemption for aspirational-intelligence.
- **The corpus-floor landmark** (first Claude chat, 2025-11-11) is not a work — it
  lives as an animation constant in ho-07.2, not a `works.json` entry. Confirm it
  stays out of the data.
- **New-work relationships** — adding three core works invites new edges (shodo /
  sutra to the corpus and methodology; sageframe as a root). Author minimally here;
  deeper connectivity is ongoing authoring, not this ho's job (forward-only — the
  ho-07 the-same-lever pattern).
